# バーコードラベル作成アプリ

iPhone・iPad・MacのSafariで利用するバーコードラベル作成・印刷Webアプリです。

- JAN-13・JAN-8・UPC-Aの番号を入力してバーコード生成
- カメラからのバーコード読み取り（HTTPS・初回通信が必要）
- 商品名とバーコードを並べたラベル印刷、A4／B5対応（ラベル高さ5〜50mm）
- 商品情報は端末のブラウザ内に保存し、サーバーには保存しません

## 安全な運用

- 店舗業務の前に、実寸で印刷し、レジでバーコードが正常に読み取れることを確認してください。
- 商品名・フォルダ・印刷リストはブラウザ内に保存されます。端末を紛失、初期化するとデータを失う可能性があります。定期的にバックアップを保存してください。
- バックアップ時に8文字以上のパスワードを入力するとAES-256-GCMで暗号化したJSONを保存します。復元時も同じパスワードが必要です。パスワードはアプリ内に保存しません。パスワードを忘れると暗号化バックアップは復元できません。
- 従来の暗号化されていないJSONバックアップも、引き続き読み込めます。パスワードが空欄の場合、バックアップは暗号化されません。
- カメラ読み取りにはバージョン固定のZXingライブラリを使用し、配信されたJavaScriptはSHA-384 Subresource Integrityで照合します。改ざんされたファイルの実行はブラウザによりブロックされます。初回のカメラ利用にはインターネット接続が必要です。

## 回帰テスト

Node.js 20以上で、追加パッケージをインストールせずに実行できます。

```sh
node --check app.js
node --check sw.js
node --test tests/regression.test.mjs
```

GitHub Actions はmainへのpushとpull requestで同じ検査を行います。JavaScriptの構文・主要バーコード規則・保存失敗・カメラ停止競合・バックアップ互換と暗号化・CSP・印刷CSSをカバーします。iOSの実機カメラ・印刷・Safariレイアウトは別途実機確認が必要です。

GitHub Pagesで公開する場合は、Settings → Pages → Deploy from a branch → main / (root) を選択してください。

## 追加監査への対応

- 商品・印刷リスト・フォルダは1つの保存データにまとめ、1回の書き込みで確定します。旧保存キーは消さずに残し、新形式がないときだけ読み込みます。旧バージョンへ戻すと、新形式で保存した更新が見えなくなるため、先に最新版でバックアップを保存してください。
- JAN-13の標準倍率に合わせ、基本の棒の高さは22.85mm、画像全体は26.73mmです。UPC-Aは左右9モジュールの余白を確保します。30mm以上ではこの寸法を使用し、5〜25mmでは従来の小型表示・印刷を使用します。5・10mmでは下の数字を省略します。小さいサイズは読み取りにくい場合があるため、サイズを自由に選んで試し刷りで確認してください。実際の印刷品質・倍率・用紙によって結果が変わるため、レジでの確認は必要です。
- バックアップの同一印刷項目（番号・商品名・枚数）は、選択状態と改行位置を復元します。保存商品の重複は従来どおり追加・上書きしません。
- 読み取り形式をEAN-13・EAN-8・UPC-Aに限定し、結果の形式も確認します。QRコードなどの数字をJANとして採用しません。SRIによる外部プログラムの改ざん検知は維持します。
- Service Worker（オフライン用ファイルを管理する仕組み）は、画面・処理・デザイン等のファイルの照合値を確認して一式保存します。使用中のアプリへ強制切り替えせず、すべてのタブ・ホーム画面アプリを閉じた後に新しい版を使用します。画面は保存済みの同一版を優先し、一部の通信失敗で新旧を混ぜません。

## 保存データの保護

起動時に端末内の商品・印刷リスト・フォルダの管理番号重複やデータ異常を検査します。異常時には保存を停止し、元の保存データを自動修復・削除・上書きしません。警告が消えない場合は、ブラウザのデータを消去せず、表示される「元データを退避（未暗号化）」で復旧用の原本をファイル保存してください。このファイルは通常のバックアップとは異なり、アプリに直接復元できません。安全な場所に保管し、復旧前にデータを確認してください。正常時は従来どおりJSONバックアップ（パスワード設定時は暗号化）を使用できます。
